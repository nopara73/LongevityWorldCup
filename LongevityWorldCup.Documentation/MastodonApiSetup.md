# Mastodon announcements

Mastodon uses a free server account and a user access token. The announcement account is
<https://mastodon.social/@longevityworldcup>, marked as an automated account. Normal account
creation, email confirmation, and the server's rules and terms must be completed before
creating the announcement application.

Create an application named **Longevity World Cup announcements**, with website
`https://longevityworldcup.com/`, redirect URI `urn:ietf:wg:oauth:2.0:oob`, and only these scopes:

- `profile`: verify the token's account identity.
- `write:statuses`: publish announcements.
- `write:media`: upload images and their alt text, including processing-status checks.

Save the issued credentials in the owner's secret store. Never put real credentials in
the repository, setup artifacts, screenshots, or test fixtures. The login password and
OAuth client secret are account/recovery credentials; the website only needs:

```json
{
  "MastodonServerUrl": "https://mastodon.social",
  "MastodonAccountId": "<verified account ID>",
  "MastodonAccessToken": "<restricted user access token>"
}
```

These are fields of the existing protected production `config.json`. Do not write them
on the owner's behalf when the owner has reserved secret storage to themselves. Preserve
the current X, Threads, and Facebook token state when applying any configuration change;
see [ServerDeployment.md](ServerDeployment.md). Restart the service after changing config.
The client requires HTTPS, rejects redirects, and verifies the account ID before posting.

The daily job selects at most one eligible Event at **15:04 UTC**. The minute queue handles
selected Custom Events and retries of prepared announcements. Mastodon follows the existing
athlete eligibility, seven-day freshness, and two-day subject cooldown rules. Donation
acknowledgments and Custom Events do not expire under athlete-highlight freshness rules.
This channel publishes Events without filler posts.

The Custom Event Designer has a separate Mastodon destination, preview, and exported
`sendToMastodon` flag. Text uses a 500-grapheme budget and a 23-character URL allowance.
Long announcements use the existing image renderer with plain-text alt text. Other-platform
contact handles are resolved to athlete names. Link cards are generated by Mastodon.

`SocialDeliveryChannels` baselines pre-existing Events once. `SocialDeliveries` records
destination selection, prepared request and media ID, deterministic idempotency key,
retry timing, and the verified remote receipt. It preserves any earlier channel's ledger.
Disabled credentials leave selected Events pending. The two jobs share a dispatch gate.

Mastodon's idempotency cache lasts up to one hour. After an uncertain write, retries reuse
the exact request and key inside a conservative 45-minute window. If the receipt is still
unknown after that window, the ledger becomes `review` / `UnconfirmedPost` and automatic
resubmission stops. Review the account's public posts and reconcile that row before retrying;
do not blindly clear it. A known rejection such as HTTP 401 or 429 remains retryable, while
a previous uncertain outcome is still retained. Successful receipts finish delivery once.

[media](https://docs.joinmastodon.org/methods/media/),
[scopes](https://docs.joinmastodon.org/api/oauth-scopes/), and
